# 05 · 发布与回滚手册

适用对象：`usage-contract-replay`（当前 `0.1.0`，零依赖、纯 Python、纯函数 CLI）。
本手册区分**当前可执行**的步骤与**目标能力建成后**才能执行的步骤，后者明确标注
"（待开发，G*）"。本手册不包含重新实现计费的内容。

## 1. 当前部署形态事实

- 无数据库、无网络、无凭据、无后台进程；交付物是 `src/usage_contract_replay/` 包 +
  本地 JSON 输入，CLI 从文件读入、向 stdout 打印 JSON。
- 唯一运行入口：`PYTHONPATH=src python3 -m usage_contract_replay.cli [input.json]`。
- 唯一测试：`python3 -m unittest discover -s tests -v`（1 个用例）。
- 输出确定性已验证：同一 fixture 连续两次运行字节一致（`sort_keys=True`）。
- 因为没有持久化与状态机，当前"回滚"只有代码层含义；数据层/发票层回滚是待开发能力。

## 3. 发布步骤

### 3.1 当前流程（代码级发布）

1. 从 `main` 切发布分支，完成评审；
2. 本地执行 C1–C8 并保存命令输出到发布工单；
3. 打 git tag（建议 `vX.Y.Z`，与 `pyproject.toml` 的 `version` 一致）；
4. 合并主干；部署方式当前为"同步代码 + 本地 fixture 运行"，无独立服务需要重启；
5. 在发布工单记录：tag、fixture 输出哈希、测试输出。

### 3.2 未来流程（具备持久化与编排后，待开发）

在 3.1 基础上增加：

1. **影子重放（shadow）**：新版本对生产事件副本只计算不落账，与旧版本输出逐发票 diff；
2. **兼容性路由**：按 `schema_version` 分流 v1/v2 输入（兼容矩阵第 4 节）；
3. **灰度账户名单**：先单账户、再小范围，每批对比 `delta` 汇总；
4. **冻结窗口避让**：账期末关账前后 1 个工作日不发布影响计费口径的变更（⚖️ O9）；
5. 追溯类合同变更禁止搭车发布，必须独立走 [04](04_contract_retroactive_change.md) 流程。

## 4. 回滚手册（三级）

### L1 · 代码回滚（当前可用）

- 触发条件：C2/C3/C4 任一失败，或发布后发现输出信封/金色 fixture 偏离。
- 动作：`git revert <发布合并提交>` 或 `git checkout <上一 tag>`，重跑 C2–C4 确认恢复。
- 数据影响：**无**。当前管线不写库，回滚代码即完全恢复，历史 JSON 输入不受影响。
- 时限：分钟级。

### L2 · 合同/配置回滚（待开发，依赖 G6/G14）

- 触发条件：合同新版本口径错误（价格、免费额度、阶梯配错），但代码本身正常。
- 动作：
  1. 立即把错误版本标记失效，恢复上一版本的 `effective_from` 区间；
  2. 对错误版本生效期间的全部发票执行 [04](04_contract_retroactive_change.md) 的
     dry-run 影响报告；
  3. `draft` 发票重算覆盖；`frozen` 发票只生成冲红/补差，禁止改写原发票；
  4. 归档报告与审批记录。
- 禁止：删除错误合同版本（审计链断裂）；手工编辑派生金额字段。

### L3 · 数据/事件回滚（待开发，依赖 G1/G14）

- 触发条件：上游计量错误导致大面积事件污染（重复洪流、单位标量错误、撤回风暴）。
- 动作：
  1. 先在摄入侧停流或隔离问题 `event_id` 区间，**不删除事件**（R2）；
  2. 用隔离后的事件集对受影响账期整体重放；
  3. 重复事件按 R1 折叠、撤回按 R3 排除后，差异走冻结/未冻结分流；
  4. 输出影响范围报告，财务确认后落补差。
- 禁止：直接改库修金额、绕过重放手工冲账、在没有 `event_id` 身份的情况下做去重
  （当前正是此状态，所以 L3 现在**不可执行**，只能等 G1 落地）。

## 5. 回滚触发判据速查

| 观测信号 | 级别 | 首要动作 |
| --- | --- | --- |
| 单测/金色 fixture 失败 | L1 | 代码 revert |
| 单张发票金额投诉且可复现 | L2 评估 | dry-run 双跑，确认合同口径 |
| 批量发票同方向偏移 | L2/L3 | 先隔离输入，再决定配置还是数据回滚 |
| 输出出现负金额（非冲红单据） | L2 | 现行 v1 已知会产生负账单（G9），发布前用 C9 拦截 |
| 重放结果两次运行不一致 | L1 | 停止发布，定位非确定性来源后再走流程 |
| 裸 `KeyError`/栈追踪出现在业务输入上 | L1 | 输入校验缺失（G12），回滚并补 fail-fast |
